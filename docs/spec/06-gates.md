# 06 — Gates

Gates are Strata's immune system: deterministic checks that block low-quality code from landing, run at the moment of editing, at the end of a turn, at commit, and in CI. Code-quality gates **block** (D-008).

## 1. Gate model

A gate is one tool invocation with a contract:

```toml
# .strata/gates.toml
[[gate]]
id = "go-lint"
desc = "golangci-lint with the strata profile"
applies_to = ["**/*.go"]
exclude = ["**/testdata/**", "**/*_gen.go"]
stages = ["edit", "stop", "commit", "ci"]
mode = "check"                   # check | fix (fix = may modify files; runs before checks)
blocking = true                  # false = advisory (warn); see ratchet §5
scope = "package"                # file | package | repo — how {targets} is expanded
cmd = ["golangci-lint", "run", "--config", ".golangci.yml", "{targets}"]
edit_cmd = ["golangci-lint", "run", "--fast-only", "{targets}"]   # optional cheaper variant for the edit stage
timeout = "60s"
parser = "golangci-json"         # how output is parsed into findings (§6)
baseline = ".strata/baselines/go-lint.json"   # optional ratchet baseline
docs = "go-lint-standard"        # shard id explaining the gate (required for custom gates)
```

`{targets}` expands per `scope`: `file` → the changed files; `package` → their containing packages/modules; `repo` → `./...` or the tool's repo-wide default.

Additional keys (recorded during the build):

| Key | Meaning |
|---|---|
| `check_cmd` | for `mode = "fix"` gates: the non-modifying variant run when fixes are not allowed (e.g. `gofumpt -l`); without it a fix gate is skipped in that run |
| `workdir` | repo-relative directory the command runs in (`{targets}` are relative to it; tool-reported paths are mapped back to repo-relative) |
| `repo_target` | what `{targets}` expands to for `scope = "repo"` (default `.`; Go uses `./...`) |
| `config_files` | extra files whose content is part of the results-cache key (e.g. `.golangci.yml`) |
| `builtin` | `suppressions` or `strata-lint`: an engine-implemented gate with no `cmd` |
| `lines_regex` | regex for the `lines` parser; named groups `file` (required), `line`, `col`, `severity`, `message` |
| `severity` | default severity for findings whose parser carries none (`exitcode`, `lines`, `sarif`) |
| `disabled` + `reason` | turn a gate off; `reason` is required |

Defaults: `mode = "check"`, `scope = "file"`, `parser = "exitcode"`, `timeout = "60s"`, `stages = ["stop", "commit", "ci"]`, `blocking = true`. A blocking gate blocks on findings of severity `warning` or worse (`strata-lint`: `error` only). Infrastructure problems never block: a tool missing from `PATH` and a timeout are reported as advisory warnings (`tool-missing`, `timeout`); output that cannot be parsed from a failing tool is one blocking `tool-failed` finding.

## 2. Stages

| Stage | Trigger | Targets | Time budget | Blocking mechanism |
|---|---|---|---|---|
| `edit` | PostToolUse on Edit/Write/MultiEdit (and NotebookEdit) | the touched file(s) | ≤ 2 s typical | exit 2 → stderr fed back to Claude, who must fix before moving on |
| `stop` | Stop / SubagentStop hook | all files changed in the working tree vs. `HEAD` (+ untracked, not ignored) | ≤ 60 s | `decision: block` with findings; bounded (§2.1) |
| `commit` | git pre-commit hook installed by `strata init` (`strata check --staged`) | staged files | ≤ 90 s | non-zero exit aborts commit |
| `ci` | GitHub Actions workflow generated by `strata init --ci` | repo | unbounded | failing check |

Order within a stage: `fix`-mode gates first (formatters, auto-fixers), then `check`-mode gates, so Claude never receives a finding a formatter would have fixed. Gates in the same phase run in parallel (bounded by CPU count); output is collated deterministically by gate id.

### 2.1 Stop-stage loop guard

The Stop hook blocks completion while blocking gates fail. To avoid infinite loops: the hook reads `stop_hook_active` and a per-session counter in `.strata/session/<id>.json`. It blocks at most `[gates] stop_max_blocks` (default 3) consecutive times for the *same* finding set; if findings are unchanged after that, it allows the stop, prints a loud summary (`✗ 4 blocking findings unresolved — see strata check`), and records a `gate` telemetry event with `result: abandoned`. Progress (finding set shrinks) resets the counter.

## 3. Findings and feedback format

All gate output is parsed into normalized findings: `{gate, rule, severity, file, line, col, message, fix_hint, docs}`. What Claude sees on a blocking failure (stderr from the hook, ≤ 40 lines, most severe first, grouped by file):

```
strata gates ✗ 3 blocking findings (edit stage)
engine/internal/search/rank.go
  42:9   go-lint/gocognit   cognitive complexity 27 > 20 in rank() — extract the multiplier logic   [standard: go-complexity-limits]
  88:2   go-lint/errcheck   error return of rows.Close not checked
engine/internal/search/rank_test.go
  10:1   go-fmt             file not gofumpt-formatted (auto-fix failed: syntax error at 12:4)
Fix these, then continue. Explain a gate: strata gates explain go-lint/gocognit
```

`strata gates explain <gate>/<rule>` prints the rule's rationale from the linked shard plus the tool's own documentation pointer.

### 4.6 Cross-cutting security

| Gate | Tool | Stages |
|---|---|---|
| `secrets` | `gitleaks protect --staged` / `gitleaks detect` | edit (file), commit, ci |
| `sast` | `semgrep` with `p/default` + language packs + `.strata/semgrep/*.yml` custom rules (taint-mode rules for command injection, path traversal, SQL injection, SSRF) | stop (changed files), commit, ci |
| `deps` | `osv-scanner` across lockfiles | commit, ci |
| `suppressions` | built-in | edit, commit — see §7 |

Custom semgrep rules shipped by Strata include: no `shell=True` / `sh -c` with interpolation; no `curl … | sh` in scripts; no reading files under `knowledge/_private/` from scripts; no network calls from scripts declared `read-only` (heuristic, by import/call patterns).

## 5. Baselines and the ratchet

Dropping Strata into an existing repo must not produce a wall of errors that blocks all work. Baselines solve this:

- `strata gates baseline <gate>` records current findings as `{rule, file, fingerprint}` (fingerprint = hash of rule + normalized source line + enclosing symbol, stable under unrelated line shifts).
- With a baseline, a gate **blocks only on findings not in the baseline**. Baselined findings are reported as a count (`+ 212 baselined`).
- **Ratchet:** the baseline may only shrink. `strata check` rewrites the baseline file when findings disappear (fixed findings are removed, only for files the run covered; `--no-ratchet` disables this); hooks never rewrite baselines. Adding entries requires `strata gates baseline <gate> --accept` (a human/gardener-PR act, never done by the edit hook); without `--accept` the command reports what would be added.
- A gate with an empty baseline for 14 days has its baseline file deleted by the gardener.
- New gates proposed by the gardener start as `blocking = false` (advisory) or with a baseline, then are flipped to blocking only when the current codebase passes ([07](07-gardener.md) §5.2).

## 6. Output parsers

Built-in parsers normalize tool output: `golangci-json`, `ruff-json`, `pyright-json`, `eslint-json`, `tsc-text`, `semgrep-sarif`, `gitleaks-json`, `shellcheck-json`, `clippy-json`, `go-test-json`, `sarif` (generic), `lines` (regex `file:line:col: message`), `exitcode` (no parse; whole output as one finding). Adding a gate for an unsupported tool uses `sarif` if the tool emits SARIF, else `lines` with a configurable regex.

## 7. Suppressions

Inline suppressions (`//nolint`, `# noqa`, `// eslint-disable`, `# nosemgrep`, `#[allow]`) are allowed only with a rule id and a reason:

```go
//nolint:gosec // G304: path is validated by repo.SafeJoin above; see [[path-safety]]
```

The built-in `suppressions` gate rejects bare suppressions, suppressions without a reason ≥ 15 chars, and file-wide/blanket suppressions. Disabling a gate in config requires a `reason` key and is reported by `strata doctor`.

## 8. Performance and caching

- Edit-stage gates must keep their *typical* latency under 2 s; gates with no fast mode are stage-restricted (`stages` without `edit`).
- Results cache: `(gate, tool version, config hash, target content hash)` → findings, stored in `.strata/cache/gates/`. The tool version is approximated by the resolved binary's path, size and mtime (no extra `--version` process per run); the config hash covers the gate definition, the expanded argv and `config_files`; repo-scope gates hash every file in the repository. Fix-mode runs are never cached. Unchanged inputs skip re-running (big win for Stop stage after edit stage already ran).
- `strata check --changed|--staged|--all|<paths>` is the manual entry point and is exactly what hooks call.

## 9. Engine repo gates

The Strata engine repository runs the strict profile for Go + TypeScript + shell + docs + security, at blocking level, with **no baselines** (greenfield) and these additional requirements: coverage ≥ 80% per `internal/` package, fuzz targets for every parser (`doc`, `search` query, frontmatter, hook stdin), benchmarks for every budgeted operation ([01](01-architecture.md) §7), and `go test -race` clean.
